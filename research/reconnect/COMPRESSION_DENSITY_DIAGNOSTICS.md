# 平滑压缩三密度：保存误差与预算诊断

2026-11-07，Asia/Shanghai。承接 c2ced9c 的唯一 N64 物理单例，本轮只读保存数据。Stage3 incomplete，fluid ORC 关闭，κ未算，累计记录仍506。

本轮得到两项可以影响下一步安排的结论：

1. kernel中时误差变差，并非有符号交叉项变成了正数：两个时刻的交叉项均为负，中时的正平方项更大，终时负交叉项占优。终时误差减小包含与原离散误差的抵消，不能单凭该结果宣称密度更准。
2. 对当前保存的ledger收益，单独消除参考空间/时间指标后，剩余预算仍高于四项收益；终时浓度和H分别为收益的2.498倍、4.847倍。反过来，终时的参考空间单项也分别大于浓度/H收益，两个时刻H均有此障碍。因此不能只追加参考精化，也不能把只追加一个时间档当作充分方案；应先定义时间与参考误差的联合控制。

## 浓度误差为何随时刻变号

令e_o=u_o-R，d=u_s-u_o，V0=σ64²，使用原物质质量内积。恒等式为

`(‖u_s-R‖_m²−‖u_o-R‖_m²)/V0 = 2〈e_o,d〉_m/V0 + ‖d‖_m²/V0`。

平方变化除以两来源相对误差之和，恢复原相对误差变化。没有改变c、R、m或分母。表内是归一化的**平方误差变化**，不是前一轮报告中的误差本身。

|来源/时刻（K32）|有符号交叉项 2〈e_o,d〉/V0|状态差平方项 ‖d‖²/V0|相对误差平方变化|
|---|---:|---:|---:|
|kernel / 0.025|-6.683547897986e-10|9.885928135002e-10|3.202380237016e-10|
|kernel / 0.05|-3.509116073755e-09|2.234538256407e-09|-1.274577817348e-09|
|ledger / 0.025|-6.619590609803e-11|9.643554318354e-12|-5.655235177968e-11|
|ledger / 0.05|-3.309053159621e-10|1.514866617146e-10|-1.794186542476e-10|

kernel中时：−6.68355e−10 + 9.88593e−10 = +3.20238e−10，总误差增大；终时：−3.50912e−9 + 2.23454e−9 = −1.27458e−9，总误差减小。K16也保持相同方向，完整8行见results.json。这是保存场之间的代数归因，不是密度模型误差来源的因果识别，也不是可用来拟合新系数的目标函数。

ledger两个时刻的交叉项同样为负，净平方误差变化为负；这只说明点估计略小，其改善仍未超过原完整预算，不能利用恒等式改判。

## H为何能改善，而中时浓度场反而变差

取o_c=u_o−mean_m(u_o)，d_c=d−mean_m(d)，则

`H_s−H_o = −[2〈o_c,d_c〉_m+‖d_c‖_m²]/V0`。

这里交叉项的对象是原场的中心化波动；浓度误差恒等式中的对象是相对参考的残差e_o，二者不同。H是全局方差指标，对浓度场误差的改善不能作替代判断。保留实际mean_m(d)和M·mean_m(d)²，没有将微小质量漂移强设为零。

|来源/时刻（K32）|负二倍中心化交叉项|负中心化平方项|有符号 H 变化|
|---|---:|---:|---:|
|kernel / 0.025|3.261225232802e-05|-9.885928135002e-10|3.261126373555e-05|
|kernel / 0.05|6.453287383017e-05|-2.234538256407e-09|6.453063929213e-05|
|ledger / 0.025|4.789584857993e-07|-9.643554318354e-12|4.789488423640e-07|
|ledger / 0.05|3.332149520366e-07|-1.514866617146e-10|3.330634655851e-07|

本例两来源的H均仍在参考H之下，因此这些正的有符号H变化对应H绝对误差减少。审计分别核对有符号变化和绝对误差变化，未将两者普遍等同。
